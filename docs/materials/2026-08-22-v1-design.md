# Native materials v1: design

**Status:** approved 2026-08-22 after three review cycles; slice 0 implemented
and verified passed-with-caveats in fork `materials-26.04` at `3792432a`
(`niri-experiments/docs/results/2026-08-22-slice0.md`). Slice 1 is implemented
and merged at `ec0824c5`; nested-winit verification against the earlier
`2a55ab14` implementation is passed-with-caveats at `niri-experiments` commit
`d155e90`. The subsequent per-render-target damage correction at `59f68905`
is covered by the final live run. Slice 2 is implemented on `slice2-glass`
through `66c42f5e`; its nested-winit verification is passed-with-caveats at
`niri-experiments` commit `98a01e7b`.
**Companion:** `niri-experiments/docs/research/2026-08-22-gap-analysis.md`

## Goal

Recreate niri-glass natively inside a niri fork: a **material** system where a
window's visual treatment is part of the compositor's own rendering — exact
interpolated positions, the presentation clock, the window texture as a shader
input — instead of an external client chasing IPC state. v1 ships one built-in
material type, `glass`, assigned per window by name.

## Decisions

| Decision | Choice |
| --- | --- |
| Compositor | niri only, forked (in-compositor material engine) |
| v1 material kinds | Built-in `glass` with parameters; user-defined GLSL deferred until upstream #913's shader contract exists to converge on |
| Concept name | `material` (`surface`/`texture` collide with Wayland/GL terminology) |
| During niri's open/close/resize animations | Material renders inside the tile's animation offscreens — window+glass animate as one unit |
| Window-content compositing | Preserve opaque window pixels; refracted background contributes only through window transparency. Full material freedom over content remains available to later material types (the window texture is a shader input), not to v1 glass |
| Redraw policy | Continuous redraw is slice-0 scaffolding only; durable v1 damages on window damage, background damage, and uniform/config change; jelly rides niri's existing animation redraw loop |
| Per-workspace assignment | Deferred from v1 (window-rules only) |
| Existing Quickshell client | Frozen: no new features, remains supported and the parameter reference while unpatched niri is supported; "retired" means no longer preferred, not removed |

## 1. Fork and repository layout

- Branch `materials-26.04` is stacked on `patched-26.04` in `niri-material`.
  The two #4147 IPC commits stay because they serve external IPC clients and
  the open PR; native materials do not need them.
- Production compositor and shader sources live in `niri-material`, beside
  their compiler and tests (`src/render_helpers/shaders/`). Stable material
  specifications and implementation plans live in `docs/materials/`.
- Research, results, and source fixtures live in the sibling
  `niri-experiments` repository.
- The legacy `niri-glass` repository retains the frozen Quickshell reference
  implementation and its parameter sources. It is not a source of truth for
  production shaders, specifications, plans, or experiment results.
- Rebase budget per gap analysis §4: about three integration cycles per year
  plus one potentially heavy renderer-refactor rebase (#3833/#3834).

## 2. Material core

**State.** `MaterialState`, retained on `Tile`:
- the resolved material reference (name + resolved parameter set),
- current uniform values,
- its `OffscreenBuffer`,
- stable element `Id` and `CommitCounter` state.

It retains neither texture clones nor background-buffer references. Textures:
`OffscreenBuffer`/`EffectBuffer` recreate their texture when a clone survives
into the next render (`is_unique_reference`, offscreen.rs:114,
effect_buffer.rs:179); textures are resolved during `draw()`, following
`XrayElement`. Background: each output owns an `Xray` with separate
`background` and `backdrop` `EffectBuffer`s per render target — output,
screencast, screen capture (`xray.rs:27-28`) — so both buffers are selected
per render, `ctx.xray.background[ctx.target]` and
`ctx.xray.backdrop[ctx.target]`, and those `Rc`s live only in the transient
element. The element composes background, backdrop, and the workspace/
backdrop colors exactly as `XrayElement` does, taking damage from whichever
buffers and color metadata contribute, so glass renders correctly when no
wallpaper surface exists instead of sampling transparent black.

**Element.** `MaterialRenderElement`, a new `TileRenderElement` variant built
on niri's multi-texture `ShaderRenderElement` machinery (named samplers +
named uniforms). Smithay's `GlesTexProgram` is single-sampler (`tex`) and is
not used. Inputs in v1: the window texture (or composed offscreen, below), the
per-target background and backdrop textures, and the workspace/backdrop
color uniforms, per the composition paragraph above. Pushed from `Tile::render_inner`, so it lands inside
open/alpha animation offscreens by construction, and overview handles it via
the existing `Crop → Rescale → Relocate` wrappers.

**Programs.** v1 has exactly one program: the built-in glass shader, compiled
once per EGL context via niri's existing `Shaders` pattern — material
definitions contain parameters, not GLSL, so there is nothing per-definition
to compile. Windows carry only a material selection plus uniform values;
same-name parameter reloads update `MaterialState` in place, while a change in
the resolved name swaps it. Reload validates parameters, with no
compilation involved. If the built-in program fails to compile on a context
(driver quirk), material windows on that context render as plain windows with
a loud warning — the same fallback shape as niri's own optional shaders.

**Composition with the resize animation.** The resize path replaces the
window with a `ResizeRenderElement` (snapshot + live offscreen crossfade,
tile.rs:1087–1140). For material windows, that element is rendered into the
material offscreen and the material is applied to the result — one extra
pass, keeping the two shaders decoupled. Open/alpha composition is automatic
(the material element is inside the offscreen the animation renders).

**Damage.** Slice 0 forces continuous redraw to get pixels on screen fast.
Durable v1: the element damages when the window damages, when any
contributing background/backdrop buffer or color metadata changes (per the
composition paragraph above), and when uniforms change (config edit, focus
change, motion state); static glass at rest contributes no damage. Motion-driven uniforms
(jelly) change only while niri animations/gestures run, so they ride the
existing `unfinished_animations_remain` redraw loop.

**Compositing contract (v1 glass).** Premultiplied alpha throughout, matching
the renderer's global `ONE, ONE_MINUS_SRC_ALPHA` blend state. `glassed_bg` is
a premultiplied RGBA value: its color is the refracted, attenuated background
plus additive slab terms (specular, edge glint); its alpha is the slab
coverage at that fragment — 1 inside the slab, feathering to 0 at the slab
silhouette, 0 outside. Then:

```
out.rgb = win.rgb + (1 - win.a) * glassed_bg.rgb
out.a   = win.a   + (1 - win.a) * glassed_bg.a
```

where `win` is the premultiplied window/offscreen texture, rendered into the
material offscreen at alpha 1.0. Opaque window pixels pass through untouched;
outside the window area the equation reduces to the slab alone. Window-rule
`opacity` is applied exactly once, as the final element alpha on the material
element's output (the standard `niri_alpha` path) — never inside the shader
and never during the offscreen render, so it cannot be multiplied twice.

## 3. Config

**Definitions.** Top-level multipart blocks, following the `window-rule`
dispatcher precedent:

```kdl
material "frost" {
    glass {
        ior 1.5
        thickness 20
        // ...
    }
}
```

Validation, enforced at parse/resolve time (invalid config is rejected whole,
like any niri config error):
- duplicate material names are an error;
- exactly one material type block per definition;
- every numeric parameter is range-checked;
- a window-rule referencing an unknown material name is an error.

**Assignment.** A `material "name"` field on window-rules: a **scalar** —
last matching rule wins (no merging). Matching is the existing dynamic rule
machinery, so `is-focused`-conditioned rules work; a change in the resolved
material name invalidates and swaps the tile's `MaterialState` (a real
swap path — a new resolved parameter/uniform set — not free, and built as
such from the start). Per-workspace assignment is deferred from v1; when it
returns it must specify window-level opt-out and cross-workspace move
semantics.

**Reload failure policy.** Config that fails validation is rejected whole
(niri keeps running on the previous config, as today). There is no shader
compilation at reload in v1; the only compile-failure mode is the built-in
program failing at context creation, handled in §2 (plain-window fallback,
loud warning).

## 4. Glass v1

**Parameters.** All optional; an omitted parameter takes the default below
(the proven `niri-glass.json` values). A value outside its range is a config
error. Colors use niri's existing config color syntax (e.g. `"#dfe8ff"`);
lengths are logical pixels.

| Parameter | Type | Default | Range |
| --- | --- | --- | --- |
| `ior` | float | 1.5 | 1.0–3.0 |
| `thickness` | float, logical px | 20 | 0–200 |
| `attenuation-color` | color | `#dfe8ff` | any color |
| `attenuation-distance` | float, logical px | 60 | > 0 |
| `chromatic-aberration` | float | 0 | 0–1 |
| `distortion` | float | 0 | 0–1 |
| `distortion-scale` | float | 0.5 | 0–2 |
| `samples` | int | 4 | 1–8 |
| `anisotropic-blur` | float | 0 | 0–1 |
| `jelly-flex` | float | 0.004 | 0–0.02 |
| `jelly-ripple` | float | 0.06 | 0–0.5 |
| `lip` | float, logical px | 6 | 0–64 |
| `shift-x` / `shift-y` | float, logical px | 6 | −64–64 |

- `roughness` is **not exposed** in v1: without mip/prefiltered background
  storage (G4, follow-up) it cannot actually blur, and a knob that does
  nothing is worse than no knob.
- The spring-replay parameters (`springDampingRatio`, `springStiffness`,
  `springEpsilon`) are **dropped**: they existed to imitate niri's animations
  from outside. Jelly residuals derive from niri's own current-vs-target
  animation state at render time.

**Shading.** The GLSL logic ports from the reference drei-derived shaders
(refraction taps, Beer-Lambert attenuation, fresnel edge optics, chamfer
tinting), re-targeted from Qt CustomMaterial semantics to the element's
sampler/uniform contract and the §2 compositing equation — the reference
shader has no window-pixel term, so that composition is new, specified code,
not a port.

**Geometry.** Slab below the window as a fragment-faked chamfered quad (G2
quad form) on an inflated element area. True meshes deferred.

**Background sampling.** Direct sampling of the per-target `background` and
`backdrop` `EffectBuffer`s, composed with the workspace/backdrop colors per
§2. No mips in v1 (hence no `roughness`); damage-aware, buffer-owned mip
storage is the first post-v1 follow-up.

## 5. Slices

**Slice 0 — prove the renderer seam.** Hard-coded material on one test
app-id: persistent window-texture shader + background sampler, continuous
redraw, no slab, no config, no live behind-refraction. Exit criteria:
1. survives move, resize (including the resize-element composition),
   open/close, and overview transforms with no visual detachment;
2. Tracy shows **zero texture creation across repeated unchanged-geometry
   frames after warm-up** — creation is expected and allowed on first use,
   on offscreen growth, and on EGL-context replacement;
3. GPU frame-time measured before/after, recorded.

**Slice 1 — config + assignment.** `material` blocks, window-rule scalar
assignment, validation, reload + failure policy, material-swap invalidation.
Damage-on-change replaces continuous redraw here.

**Slice 2 — glass.** Full parameter set, slab quad, compositing contract,
jelly from native animation state.

**Slice 3 — overview correctness gate.** Fix the `CropRenderElement` ×
pixel-shader clipping defect (G9, `monitor.rs:1683-1703`): the inflated slab
must render correctly through overview and workspace switches. This gate
sits before acceptance because slice 2's inflated slab is exactly the
geometry the defect clips. Upstream candidate (hand-written).

**Then:** parity pass against the frozen Quickshell client in the legacy
`niri-glass` repository, physical DRM smoke, v1 acceptance.

**Slice 2 verification debt (closed).** Slice 2 preserves Slice 1's per-render-
target input fingerprints and extends them for every new pixel input: backdrop
buffer identity and commit, plus workspace/backdrop color metadata. Its live
run at `niri-experiments` commit `98a01e7b` covers the final Slice 1 code,
exercises output and capture targets, and closes the inconclusive texture-
creation and matched GPU-time measurements from commit `d155e90`. Physical DRM
remains the final v1 acceptance gate rather than a Slice 2 prerequisite.

## 6. Verification

- niri's existing test suite stays green on the fork at every slice.
- New unit tests: config validation (each rule in §3) and material-precedence
  (last-match-wins, focus-conditioned swap).
- The completed slice-0 nested procedure remains in
  `docs/materials/plans/2026-08-22-slice0.md`. The Quickshell-specific method
  at `niri-experiments/docs/research/legacy-visual-verification.md` is research
  input, not a native compositor procedure. Slice 1 recorded its run directly
  in `niri-experiments/docs/results/2026-08-22-slice1.md` and did not add a
  reusable native procedure; the Slice 2 plan owns consolidating one if the
  parity and acceptance passes will reuse it.
- Tracy gates from slice 0 onward: zero texture creation across repeated
  unchanged-geometry frames after warm-up (first-use, growth, and
  context-replacement allocations allowed); before/after GPU frame-time on
  every slice.
- A physical DRM smoke on real hardware before v1 acceptance (nested winit
  behavior is not representative — established by the IPC spike).

## 7. Deferred beyond v1

User-defined GLSL materials (converge on upstream #913 when it lands);
per-workspace assignment; lighting scenes, god rays, particles (G5); true
meshes with depth (G2 mesh form); live behind-refraction during animations
(G3 / #3833-#3834); mip/prefiltered background storage and `roughness` (G4);
color pipeline (G10); above-window material layers.

## 8. Risks

See gap analysis §4. The load-bearing ones for v1: the queued deferred-
offscreen refactor collides with §2's offscreen composition (mitigation:
slices keep the material seam narrow; shape code toward the refactor);
`ShaderRenderElement` is primary-GPU-only; material windows forfeit direct
scanout (accepted, desktop envelope).
