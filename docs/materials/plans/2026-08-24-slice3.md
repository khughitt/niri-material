# Native Materials Slice 3 Implementation Plan — G9 Overview Clipping Gate

**Status:** draft, revision 3 (post-review round 2), not yet executed.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the G9 gate: prove `CropRenderElement` over niri's pixel-shader
elements renders retained pixels correctly, and replace the monitor's HACK
crop bounds with per-workspace bounds that leave the workspace strip's actual
ends open, so the inflated glass slab renders correctly through overview and
workspace switches.

**Architecture:** Two changes plus evidence. (1) A deterministic
characterization run establishes what the 2024-era HACK comment still means
today: niri's shaders have since moved to CPU-side `input_to_geo` matrices
over `niri_v_coords`, and code analysis says that path survives cropping (the
crop wrapper hands `draw()` a consistent `(src, dest)` pair and `tex_matrix`
keeps `niri_v_coords` in fraction-of-full-element space). A force-crop
instrument build renders a static scene with the band crop on vs. off;
byte-identical frames retire the coordinate-space claim with evidence.
(2) `Monitor::render_workspaces` crop bounds become per-workspace, keyed on
the workspace's **global index in the monitor's workspace strip**: a side is
cropped exactly when the strip continues past it (another workspace exists on
that side, across the ever-present inter-workspace gap); the strip's first
top and last bottom stay open; overview keeps its both-sides card band; idle
stays unbounded. Global indices keep each workspace's bounds constant for the
whole switch — bounds keyed on the *rendered* set would snap shut the moment
a neighbor enters the viewport, a new pop. The visible payoff is confined to
strip-end void boundaries (spring overshoot / rubber-band past the first
workspace — see Findings); band-edge cuts facing the inter-workspace gap keep
their clean hard edge, which this plan treats as correct-by-design (it is the
same card treatment the overview applies) and records as such. The `niri_size` uniform mismatch found
during analysis is **documented and deferred** (no shader reads it; no
consumer, no fix — YAGNI). The damage-tracking note about maximized GTK
windows is retained verbatim in the rewritten comment and recorded as
not-exercised; this slice only ever crops less than today, so it cannot
regress that bug.

**Tech Stack:** Rust, niri v26.04 (Smithay 0.7.0 rev `ff5fa7df`), GLES2,
nested-winit live verification via the slice-2 replay harness, Tracy for the
performance record, ImageMagick for image comparison.

**Spec:** `docs/materials/2026-08-22-v1-design.md` §5 "Slice 3 — overview
correctness gate" and §6 Verification, informed by
`niri-experiments/docs/research/2026-08-22-gap-analysis.md` §G9. The defect

## Findings this plan is built on (verified 2026-08-24, rev 3)

- `ShaderRenderElement::src()` and `MaterialRenderElement::src()` both return
  the unit rect; `CropRenderElement::from_element` (smithay
  `elements.rs:145-194`) computes a sub-`src` equal to the retained fraction
  and a `geometry()` equal to the intersection. `RescaleRenderElement` and
  `RelocateRenderElement` pass `src` through untouched. So at
  `ShaderRenderElement::draw`, `(src, dest)` is always a consistent pair and
  the vertex shader's `niri_v_coords = tex_matrix * position` stays in
  fraction-of-full-element space under any `Crop → Rescale → Relocate` stack.
- Every current fragment shader (border, shadow, resize/open/close preludes,
  material) consumes `niri_v_coords` plus CPU-computed matrices or
  element-UV uniform rects. `niri_size` is declared in six shaders but read
  by **none**, while `draw()` sets it to the cropped `dest.size` — wrong
  under crop, but latent. **Deferred:** no consumer means no fix in this
  slice; the mismatch is recorded in the results doc so a future consumer
  (the material shader is the obvious candidate) fixes the uniform first.
  The HACK comment predates the matrix refactor (Feb 2024, upstream
  `340bac06`).
- Current crop policy in `Monitor::render_workspaces` (monitor.rs:1693-1703):
  fully unbounded when idle; a horizontally-infinite vertical band
  `[0, height]` for **every** workspace whenever a workspace switch **or**
  overview is active.
- **Visibility geometry** (`workspaces_render_geo`, monitor.rs:1474-1503):
  workspace bands form an index-ordered vertical strip whose bands are
  separated by an **unconditional inter-workspace gap** of
  `0.1 × view_size.h × zoom` (`workspace_gap`, monitor.rs:1362-1366) — the
  layout `gaps` setting affects window gaps only, so a 10%-of-height band of
  backdrop is visible between workspaces even during plain switches.
  Therefore bands never touch: every band edge either faces the gap toward a
  neighboring workspace, or — past the strip's first top / last bottom —
  faces open void. Cropping an edge that faces the gap is correct by design:
  it is the same card treatment the overview applies, and a workspace's slab
  must not bleed into the gap toward a neighbor. Cropping an off-screen edge
  is invisible. So the only *visible* defect in the current band policy is
  at strip-end void boundaries: spring overshoot or rubber-band past the
  **first** workspace shows void above its band, and a slab lip crossing
  that top edge is cut against the void. (The bottom strip end cannot
  exhibit this with content: niri's empty-last-workspace invariant means the
  last band with content always has an empty workspace below it.) Because
  the gap exists, bounds must be keyed on **global strip indices** — keying
  on the rendered set would flip a workspace's bounds mid-switch when a
  neighbor's band enters the viewport across the still-visible gap,
  snapping the lip off: a new pop. The slice-2 recorded "G9 vertical-lip
  clipping ... at the workspace boundary" (`niri-experiments` commit
  `a27eb8f`) is re-examined by Task 1 under this lens: a clean cut at a
  gap-facing band edge is correct behavior, to be reclassified as such in
  the results doc; a cut at a void boundary, or any displaced/glitched
  retained pixels, is the defect.
- The other `CropRenderElement` site (`scale_relocate_crop`, niri.rs:6483)
  crops layer surfaces and solid colors in the overview, never tile/material
  elements — out of scope.
- Horizontal bounds stay infinite **by design**, not by hack: the overview
  intentionally shows scrolling-layout content overhanging workspaces
  horizontally.

Add as a free function near the bottom of `monitor.rs` (outside

```rust
/// Crop bounds for one workspace's render elements, in workspace-local
/// physical coordinates.
///
/// Cropping exists to keep a workspace's elements from bleeding into the
/// inter-workspace gap toward a neighboring workspace, so each side is
/// cropped exactly when the workspace strip continues past it: in the
/// overview every workspace is a card cropped on both sides; during a
/// plain workspace switch the strip's first workspace keeps its top open
/// and the last keeps its bottom open, which keeps decorations that extend
/// past the strip's ends (shadows, decoration shaders) from being cut
/// against the void during spring overshoot or rubber-banding. Bounds are
/// keyed on the whole strip, not on which workspaces are currently
/// rendered, so a workspace's bounds stay constant through the switch.
/// With no switch or overview nothing can overflow into view, and the
/// bounds are effectively infinite. Horizontal bounds are always
/// unbounded: scrolling-layout content intentionally overhangs workspaces
/// horizontally (visible in the overview), and the output edge clips
/// everything else.
fn workspace_crop_bounds(
    height: i32,
    overview_active: bool,
    switch_active: bool,
    ws_idx: usize,
    ws_count: usize,
) -> Rectangle<i32, Physical> {
    let strip_above = ws_idx > 0;
    let strip_below = ws_idx + 1 < ws_count;

    let (top, bottom) = if overview_active {
        (0, height)
    } else if switch_active {
        (
            if strip_above { 0 } else { -i32::MAX / 2 },
            if strip_below { height } else { i32::MAX / 2 },
        )
    } else {
        (-i32::MAX / 2, i32::MAX / 2)
    };

    Rectangle::new(
        Point::from((-i32::MAX / 2, top)),
        Size::from((i32::MAX, bottom - top)),
    )
}
```
