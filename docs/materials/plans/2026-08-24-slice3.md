# Native Materials Slice 3 Implementation Plan — G9 Overview Clipping Gate

**Status:** draft, not yet executed.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the G9 gate: prove `CropRenderElement` over niri's pixel-shader
elements renders the retained pixels correctly, make the shader uniform
contract crop-invariant, and replace the monitor's HACK crop bounds with
join-aware bounds so the inflated glass slab renders correctly through
overview and workspace switches.

**Architecture:** Three small, individually upstreamable changes plus
evidence. (1) A deterministic characterization run establishes what the
2024-era HACK comment still means today: niri's shaders have since moved to
CPU-side `input_to_geo` matrices over `niri_v_coords`, and code analysis says
that path survives cropping (the crop wrapper hands `draw()` a consistent
`(src, dest)` pair and `tex_matrix` keeps `niri_v_coords` in
fraction-of-full-element space). The one contract violation left in the code
is `shader_element.rs` setting the `niri_size` uniform to the **cropped**
`dest.size`. (2) `niri_size` becomes the full element size recovered from the
retained `src` fraction. (3) `Monitor::render_workspaces` crop bounds become
per-workspace and join-aware: during a plain workspace switch a workspace is
cropped only on sides where another workspace actually joins it, so slab
lips and shadows no longer pop off at outer edges mid-switch; overview keeps
its both-sides band; idle stays unbounded. The separately-noted
damage-tracking bug (maximized GTK windows) is characterized and documented,
not gated on — this slice only ever *reduces* how much gets cropped, so it
cannot regress that bug.

**Tech Stack:** Rust, niri v26.04 (Smithay 0.7.0 rev `ff5fa7df`), GLES2,
nested-winit live verification via the slice-2 replay harness, Tracy for
performance gates, ImageMagick for image comparison.

**Spec:** `docs/materials/2026-08-22-v1-design.md` §5 "Slice 3 — overview
correctness gate" and §6 Verification, informed by
`niri-experiments/docs/research/2026-08-22-gap-analysis.md` §G9. The defect
site is the HACK comment at `src/layout/monitor.rs:1683-1703`; the uniform
contract site is `src/render_helpers/shader_element.rs:424`.

## Findings this plan is built on (verified 2026-08-24)

- `ShaderRenderElement::src()` and `MaterialRenderElement::src()` both return
  the unit rect; `CropRenderElement::from_element` (smithay
  `elements.rs:145-194`) computes a sub-`src` equal to the retained fraction
  and a `geometry()` equal to the intersection. `RescaleRenderElement` and
  `RelocateRenderElement` pass `src` through untouched. So at
  `ShaderRenderElement::draw`, `(src, dest)` is always a consistent pair and
  the vertex shader's `niri_v_coords = tex_matrix * position` stays in
  fraction-of-full-element space under any `Crop → Rescale → Relocate` stack.
- Every current fragment shader (border, shadow, resize/open/close preludes,
  material) consumes `niri_v_coords` plus CPU-computed matrices or
  element-UV uniform rects. `niri_size` is declared in six shaders but read
  by none — yet `draw()` sets it to cropped `dest.size`, which is wrong under
  crop and a trap for any future consumer (the material shader is the obvious
  candidate). The HACK comment predates the matrix refactor (Feb 2024,
  upstream `340bac06`).
- Current crop policy in `Monitor::render_workspaces` (monitor.rs:1693-1703):
  fully unbounded when idle; a horizontally-infinite vertical band
  `[0, height]` for **every** workspace whenever a workspace switch **or**
  overview is active. Consequence: at the moment a switch starts, decorations
  crossing the outer band edges are instantly cut (the slice-2-observed
  "G9 vertical-lip clipping", pinned in
  `niri-experiments` commit `a27eb8f`, results row "Vertical workspace
  switch"). Cropping at a *join* between two workspaces is correct by design
  (windows themselves crop there); cropping at *outer* edges is the visible
  defect for a 6-24 px slab lip.
- The other `CropRenderElement` site (`scale_relocate_crop`, niri.rs:6483)
  crops layer surfaces and solid colors in the overview, never tile/material
  elements — out of scope.
- Horizontal bounds stay infinite **by design**, not by hack: the overview
  intentionally shows scrolling-layout content overhanging workspaces
  horizontally.

/// Full (uncropped) element size in physical pixels for a draw call.
///
/// `ShaderRenderElement::src()` is the unit rectangle, so a cropping
/// wrapper (`CropRenderElement`) hands `draw()` a `src` equal to the
/// retained fraction of the element together with the correspondingly
/// cropped `dest`. Dividing recovers the full size, keeping shader-visible
/// values crop-invariant.
fn full_element_size(
    src: Rectangle<f64, Buffer>,
    dest: Rectangle<i32, Physical>,
) -> Size<f64, Physical> {
    Size::from((
        dest.size.w as f64 / src.size.w,
        dest.size.h as f64 / src.size.h,
    ))
}
```

```

(`src`/`dest` are `Copy` and already available in the closure; division by
zero cannot occur — `draw()` returns before this point when the damage set
is empty, and a non-empty `dest` implies a non-empty `src`.)

- [ ] **Step 3: Implement the helper**

Add as a free function near the bottom of `monitor.rs` (outside
`impl Monitor<W>`, no generics):

```rust
/// Crop bounds for one workspace's render elements, in workspace-local
/// physical coordinates.
///
/// Cropping exists to keep a workspace's elements from overflowing into a
/// neighboring workspace, so each side is cropped exactly when another
/// workspace joins it there: in the overview every workspace is a card
/// with neighbors on both sides; during a plain workspace switch the first
/// and last workspaces have an open outer side, which keeps decorations
/// that extend past the view (shadows, decoration shaders) from being cut
/// mid-animation. With no switch or overview nothing can overflow into
/// view, and the bounds are effectively infinite. Horizontal bounds are
/// always unbounded: scrolling-layout content intentionally overhangs
/// workspaces horizontally (visible in the overview), and the output edge
/// clips everything else.
fn workspace_crop_bounds(
    height: i32,
    overview_active: bool,
    switch_active: bool,
    ws_idx: usize,
    ws_count: usize,
) -> Rectangle<i32, Physical> {
    let joins_above = ws_idx > 0;
    let joins_below = ws_idx + 1 < ws_count;

    let (top, bottom) = if overview_active {
        (0, height)
    } else if switch_active {
        (
            if joins_above { 0 } else { -i32::MAX / 2 },
            if joins_below { height } else { i32::MAX / 2 },
        )
    } else {
        (-i32::MAX / 2, i32::MAX / 2)
    };

    Rectangle::new(
        Point::from((-i32::MAX / 2, top)),
        Size::from((i32::MAX, bottom - top)),
    )
}
```
